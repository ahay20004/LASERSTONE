# LASERSTONE™ Controlled Research Preview Policy
Version: 0.1 — draft for owner review; not a substitute for legal advice or a signed agreement.

## Purpose and scope
The first public release is an informational and bounded demonstration of a developing scientific platform, not a general-purpose simulation service, production research repository, or open-source licensing announcement.

## Ownership and intellectual property
The project owner reports independent personal development, outside formal university assignment and without dedicated university funding. These are owner-provided statements, not independently verified ownership determinations. Confirm employment terms, contributions, third-party dependencies, and invention disclosure obligations before publication.

Do not interpret public access to a web page or repository as permission to copy, redistribute, reverse-engineer protected components, or commercially exploit LASERSTONE. Equally, this draft does not override any rights already granted by third-party licenses. Do not add an unreviewed LICENSE file or assume the repository's contents are all proprietary.

Do not publicly disclose potentially patentable implementation details before an appropriate novelty and filing review.

## Preview access
- VISITOR: view public documentation and expressly released synthetic examples.
- RESEARCHER: invitation plus owner approval, after secure backend authorization exists.
- COLLABORATOR: explicit per-project permissions, revocable by the owner.
- OWNER: approves users, published datasets, feature releases and access policy.
All private endpoints must deny access by default; client-side hiding is not access control. No researcher login is currently operational.

## Contributions and feedback
General feedback may be invited through a separately configured, moderated channel. Never ask users to post passwords, access tokens, unpublished data, personal information, or confidential inventions in public issues. Submission of a suggestion does not by itself assign copyright, patent rights or ownership. Code contributions and joint inventions require explicit contributor terms reviewed before acceptance. Security disclosures require a private reporting channel.

## Scientific publication
All released scientific results must carry provenance and status: MEASURED / DERIVED / SIMULATED / PREDICTED; version, inputs, units, uncertainty and limitations where available. Never claim validation merely from parsing or visualization. Examples are synthetic unless explicitly documented otherwise.

## Launch gates
1. Owner reviews IP status, repository visibility, dependencies, contribution rights and confidentiality.
2. Security review of public assets and deploy configuration; no secrets, sensitive code or private datasets.
3. Owner approves final wording, privacy notice, feedback channel and public release scope.
4. Test language switcher, RTL, accessibility and mobile behavior.
5. Deploy public static preview without research account registration.
6. Introduce invite-only research access only after server-side permission, audit and revocation tests.
